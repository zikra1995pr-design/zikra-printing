# مطبعة ذكرى — نسخة مستقلة من متجر الإبداع

الموقع مستنسخ من ملفات المتجر التي رفعتها، مع الحفاظ على تصميم واجهة الزبائن ولوحة التحكم، واستبدال اسم العلامة والرموز الافتراضية. **المتجر القديم لا يتأثر**.

## الملفات

- `index.html`: واجهة الزبائن، مستقلة عن لوحة الإدارة.
- `admin.html`: رابط منفصل للوحة الإدارة، ويستخدم بيانات حساب مطبعة ذكرى حصراً.
- `config.js`: رابط ومفتاح Supabase العام الخاص بمطبعة ذكرى، تضعه بنفسك.
- `zikra_setup.sql`: دوال الطلبات، التحقق من المدير، إعدادات الدفع ووصل التحويل.
- `manifest.webmanifest` و`sw.js`: دعم تثبيت الموقع كتطبيق PWA.
- `assets/logo.jpg`: رمز بديل مؤقت مكتوب عليه «ذكرى»؛ يمكن استبداله بشعارك الحقيقي لاحقاً.

## خطوات الإكمال (مرة واحدة)

1. افتح **مشروع Zikra-Printing الجديد** في Supabase، ثم SQL Editor → New query. انسخ ملف `zikra_setup.sql` بالكامل، ثم Run. يجب أن تظهر الدالتان `store_checkout_with_payment` و`store_is_admin` في النتيجة.
2. من Supabase → **Project Settings → API Keys / Connect** (قد تختلف أسماء الأقسام في الواجهة)، انسخ **Project URL** و**Publishable Key** الخاصين بالمشروع الجديد.
3. افتح `config.js`، واستبدل `https://YOUR_PROJECT_REF.supabase.co` بالرابط الجديد و`YOUR_SUPABASE_PUBLISHABLE_KEY` بالمفتاح العام الجديد. **لا تستخدم أبداً مفاتيح secret أو service_role أو كلمة مرور قاعدة البيانات هنا**.
4. أنشئ مستودع GitHub جديد باسم `zikra-printing`، وارفع **محتويات هذا المجلد** إلى المستودع الجديد (لا ترفعها إلى مستودع الإبداع القديم).
5. من Settings → Pages في مستودع GitHub الجديد، اختر Deploy from a branch، ثم `main / (root)`، وانتظر حتى يجهز رابط الموقع.
6. افتح رابط المتجر `https://<username>.github.io/zikra-printing/`، ولوحة الإدارة `https://<username>.github.io/zikra-printing/admin.html`، وسجل بحساب مدير مطبعة ذكرى الذي أُنشئ في Supabase.
7. أضف أول منتج تجريبي من لوحة الإدارة، ثم جرّب طلباً من واجهة الزبائن؛ تأكد من استلامه في لوحة الإدارة. لا تستخدم بيانات زبون حقيقي للاختبار.

## ملاحظات مهمة

- لم يتم نسخ منتجات أو طلبات الإبداع القديمة، ولا أي مفتاح اتصال قديم.
- لم يتم تضمين ملف APK القديم لأنه يخص متجر الإبداع وليس مطبعة ذكرى. حالياً يمكن تثبيت الموقع كتطبيق PWA؛ إنشاء APK جديد يحتاج بناء مستقل لاحقاً.
- الاستضافة لم تنشر تلقائياً، والربط مع Supabase الجديد **لن يعمل** حتى تعبّئ `config.js` وتنفّذ ملف SQL.
- الدالة تحسب أسعار المنتجات والتوصيل داخل قاعدة البيانات، ولا تأخذ السعر من المتصفح.
- خدمة دفع التحويل تظل غير مفعّلة افتراضياً، ووصل الدفع يُخزن في Bucket خاص، وليس ضمن رابط عام.
- قبل إطلاق متجر عام بعدد كبير من الزبائن، يُنصح بإضافة CAPTCHA أو تحديد معدل الطلبات لحماية صفحة إتمام الشراء من الإساءة الآلية.
- واجهة الإدارة الموروثة من الإبداع تحتوي أساساً على إدارة المنتجات والطلبات والإعدادات؛ بعض خصائص مثل إدارة البنرات أو تأكيد التحويل تحتاج استكمال واجهة مستقلة لاحقاً.
- `assets/hero-banner.png` من النسخة الأصلية، موجود للاحتفاظ به إن احتجته، لكنه غير مستخدم في واجهة المتجر الحالية.
